# EchoEar 角色表现系统第一阶段产品设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档状态 | Implemented v1.0 |
| 适用设备 | EchoEar 喵伴 |
| 适用固件 | `xiaozhi-echoear-firmware` |
| 阶段主题 | 表情导演、交互状态表情、待机微动作 |
| 目标用户 | 家庭用户，重点兼顾儿童使用场景 |

## 2. 背景

当前 EchoEar 已具备圆形屏幕、触摸、语音唤醒、语音对话、MCP 工具和在线音乐播放能力，也已经使用 `esp_emote_gfx` 播放 AAF 表情动画。然而实际体验中，设备更像“会显示几种眼睛动画的语音终端”，还没有形成稳定、连续的角色感。

当前主要问题不是渲染能力不足，而是表现层缺少统一决策：

- 多个语义情绪被映射成同一个“开心”动画，哭泣、困倦、惊讶等语义与画面不一致。
- 待机、连接、聆听等关键交互状态主要使用中性表情。
- 说话状态没有稳定的本地表情反馈，依赖云端下发情绪。
- 云端情绪、设备状态、错误提示和音乐状态之间没有优先级与恢复规则。
- 待机动画长期重复，缺少眨眼、观察、困倦等低频微动作。
- 短暂事件结束后缺少自然回落，表情容易突变或停留在不合适的状态。

蔚来 NOMI 的启发在于角色行为的连续性，乐鑫 ESP-Brookesia 的启发在于本地状态驱动、资源管理与系统反馈。本阶段保留小智现有语音、MCP 和音乐底座，只补齐本地角色表现层。

## 3. 产品目标

第一阶段要让用户仅通过屏幕，就能快速理解设备当前在做什么，并感到设备处于持续、有节制的“活着”状态。

具体目标：

1. 关键交互状态在 200 ms 内产生明确、稳定的视觉反馈。
2. 表情由本地状态兜底，不依赖云端情绪消息才能正常工作。
3. 云端情绪能够增强表现，但不能覆盖更重要的监听、错误等系统状态。
4. 待机时有自然、低频、非机械重复的微动作。
5. 所有临时表现都有明确持续时间和恢复目标，不出现表情卡死。
6. 不降低现有唤醒、音乐播放、WakeNet 恢复和语音对话稳定性。
7. 默认体验适合儿童：反馈短促、少说话、避免频繁主动打扰。

## 4. 非目标

以下内容不纳入第一阶段：

- 不整体迁移到 ESP-Brookesia。
- 不更换小智云端协议、LLM、TTS、ASR 或 MCP 架构。
- 不开启或重新设计全双工 AEC。
- 不增加电机、机械转头等硬件动作。
- 不实现完整歌曲封面、滚动歌词和唱片旋转界面；音乐阶段只预留状态接口。
- 不实现摄像头、人物识别或真正的情感识别。
- 不追求大量新增动画资产；优先修正状态逻辑并复用现有资产。
- 不让 LLM 直接控制动画文件、播放时长或系统级优先级。

## 5. 产品原则

### 5.1 状态先于情绪

用户首先要知道设备是在听、在想、在说，还是出了问题。开心、伤心等情绪只能在不影响交互可理解性的前提下表达。

### 5.2 本地先于云端

唤醒、聆听、思考、说话、连接和错误必须由设备本地立即触发。云端情绪是可选增强，超时或缺失时不能导致画面无反馈。

### 5.3 动作代替冗余语言

能用眼神、图标和短动画表达“我听到了”“我正在处理”的，不额外播放长句提示，避免儿童在设备说话期间无法继续表达。

### 5.4 克制的生命感

待机微动作应随机、低频、安静。目标是让用户偶尔注意到它“活着”，而不是持续吸引注意力。

### 5.5 可预测和可恢复

同一状态应具有一致表现。任何临时事件结束后，都必须根据当前真实设备状态重新决策，而不是简单回到固定表情。

## 6. 核心用户场景

### 场景 A：唤醒并提问

1. 用户说出唤醒词。
2. 设备立即从待机转为唤醒确认动画。
3. 在提示音结束前后进入聆听表情。
4. 用户说话期间保持稳定的聆听反馈，不随机眨眼或切换情绪。
5. 识别结束后转为思考表情。
6. TTS 开始时进入说话表情。
7. 对话结束后根据会话模式进入聆听或待机。

期望感受：设备确实听见了，并且每一步都容易理解。

### 场景 B：调用音乐工具

1. 用户要求播放歌曲。
2. 设备先进入思考状态。
3. MCP 开始搜索或解析时进入工具执行状态，可显示简短文字“正在找歌”。
4. 搜索成功后给出短暂成功反馈，再交由现有音乐播放界面。
5. 搜索失败时显示短暂失败反馈，然后回到可继续对话的状态。

期望感受：长耗时操作不是“死机”，用户知道设备正在处理。

### 场景 C：安静待机

1. 设备显示稳定的中性眼神。
2. 随机间隔出现慢眨眼、普通眨眼或轻微观察动作。
3. 长时间无人交互时逐渐表现困倦。
4. 一旦检测到唤醒、触摸、网络或电量事件，立即终止微动作并响应高优先级事件。

期望感受：有生命感，但不会持续打扰。

### 场景 D：网络异常

1. 正在连接时显示明确的连接反馈。
2. 连接超时或断网后显示错误表情、图标和简短原因。
3. 自动重连期间回到连接状态。
4. 网络恢复时短暂显示成功反馈，然后回到当前业务状态。

期望感受：用户能够区分“正在连接”和“已经失败”。

## 7. 表现系统模型

新增统一的“表情导演”概念，暂定代码模块名为 `ExpressionDirector`。所有表现请求先进入导演，再由导演决定最终画面。

```text
设备状态 ─────┐
云端情绪 ─────┤
MCP/工具状态 ─┤
音乐状态 ─────┼──> ExpressionDirector ──> 眼睛动画
网络/电量 ────┤                         顶部动画/图标
触摸事件 ─────┤                         状态文字
定时器 ───────┘                         可选提示音
```

导演至少维护以下信息：

- 当前基础状态 `base_state`；
- 当前临时事件 `transient_event`；
- 当前云端情绪 `cloud_emotion`；
- 当前显示行为 `active_behavior`；
- 行为开始时间、最短展示时间和超时时间；
- 临时事件结束后的恢复目标；
- 最近一次用户交互时间；
- 待机微动作随机调度信息。

## 8. 状态与优先级

优先级从高到低如下：

| 优先级 | 状态类别 | 典型状态 | 是否可被云端情绪覆盖 |
| --- | --- | --- | --- |
| P0 | 严重系统事件 | 致命错误、升级、关机、极低电量 | 否 |
| P1 | 用户输入 | 唤醒确认、聆听、触摸确认 | 否 |
| P2 | 设备输出 | TTS 说话、重要提示 | 否 |
| P3 | 任务执行 | 思考、MCP 调用、搜索、连接 | 否 |
| P4 | 媒体状态 | 音乐播放、暂停、缓冲 | 仅允许有限叠加 |
| P5 | 对话情绪 | 开心、伤心、生气、惊讶等 | 是 |
| P6 | 待机行为 | 中性、眨眼、观察、困倦 | 不适用 |

规则：

- 高优先级行为可以立即抢占低优先级行为。
- 低优先级行为不能打断高优先级行为，只能排队或丢弃。
- P0～P4 结束后，根据当前真实状态重新计算，而不是恢复到事件发生前的静态画面。
- 云端情绪默认设置有效期，建议 5 秒；到期后逐步回落到基础状态。
- 相同动画重复请求不重新加载资源，只刷新必要的超时。
- 任何行为都不得无限占用显示；系统级持久状态除外。

## 9. 第一阶段状态表现定义

| 状态 | 眼睛/主动画 | 图标或文字 | 进入条件 | 退出条件 |
| --- | --- | --- | --- | --- |
| 启动 | 现有启动或中性动画 | “启动中” | 设备启动 | 初始化完成或错误 |
| 连接中 | 思考或观察动画 | Wi-Fi/连接图标，“连接中” | 协议或网络连接开始 | 成功、失败或超时 |
| 待机 | 中性动画 | 时间、电量 | 无活动且可唤醒 | 唤醒、触摸、系统事件 |
| 唤醒确认 | 开心或睁眼短动画 | 麦克风图标 | WakeNet 命中 | 进入聆听，建议 300～800 ms |
| 聆听 | `listen.aaf` 与专用聆听眼神 | 麦克风图标 | 开始录音/识别 | VAD 结束、取消或超时 |
| 思考 | `thinking_one.aaf` | 可选“想一想” | 用户输入完成、等待 LLM | TTS、工具调用、失败 |
| 工具执行 | 思考动画的变体 | 简短动作文字 | MCP 调用开始 | MCP 返回或超时 |
| 说话 | 开心/自然说话动画 | 扬声器图标、字幕 | TTS start | TTS stop/abort |
| 成功 | 开心短动画 | 可选成功提示 | 工具或连接成功 | 600～1200 ms 后重算 |
| 一般失败 | 困惑或伤心短动画 | 简短失败原因 | 可恢复错误 | 1500～3000 ms 后重算 |
| 严重错误 | shocked/angry | 错误图标和原因 | 不可继续的错误 | 错误解除或重启 |
| 音乐播放 | 现有音乐显示模式 | 歌名/播放状态 | 播放开始 | 暂停、停止或播放结束 |
| 音乐暂停 | 中性或放松 | 暂停状态 | 播放暂停 | 恢复或停止 |

说明：第一阶段允许复用现有动画。语义不匹配的状态宁可使用中性或思考，也不再错误地统一使用开心。

## 10. 云端情绪映射

第一阶段保留小智服务下发的标准情绪名称，但只把它们视为 P5 表现请求。

建议映射：

| 云端情绪 | 第一阶段表现 |
| --- | --- |
| `happy` | happy |
| `laughing` | enjoy |
| `funny` | enjoy 或 happy |
| `loving` | happy，后续补充专用资产 |
| `embarrassed` | neutral，后续补充专用资产 |
| `confident` | happy |
| `delicious` | enjoy |
| `sad` | sad |
| `crying` | sad，不再映射为 happy |
| `sleepy` | idle/困倦，不再映射为 happy |
| `silly` | dizzy 或 enjoy |
| `angry` | angry |
| `surprised` | shocked，不再映射为 happy |
| `shocked` | shocked |
| `thinking` | thinking |
| `winking` | happy；有专用资产后替换 |
| `relaxed` | idle |
| `confused` | dizzy |
| `neutral` / `idle` | idle |
| 未知值 | 忽略并记录日志，不改变当前表现 |

云端情绪不得打断聆听、说话、思考、工具执行、连接、错误和音乐主界面。

## 11. 待机微动作设计

### 11.1 微动作集合

第一阶段至少支持：

- 普通眨眼；
- 慢眨眼；
- 快速双眨眼；
- 短暂左右观察；
- 长时间无交互后的困倦表现。

如果缺少对应动画资产，可以先使用现有 idle 动画的不同片段、速度或播放次数实现；新增资产作为独立任务评审。

### 11.2 调度规则

- 仅在 P6 待机状态运行。
- 首次进入待机后至少稳定 5 秒，再允许微动作。
- 普通微动作随机间隔建议为 8～25 秒。
- 同一微动作不连续出现两次。
- 30 秒内最多执行 3 次明显微动作。
- 深夜或静音模式下不播放配套提示音。
- 连续 5 分钟无人交互后允许进入困倦状态，但 WakeNet 必须继续工作。
- 唤醒、触摸、连接异常和电量事件必须立即取消待机微动作。

随机时间需要带有限制的抖动，不能使用固定周期，也不能出现长时间连续动画。

## 12. 说话表现

第一阶段不做口型识别，但应保证 TTS 期间有稳定反馈：

- 收到本地 `tts start` 时立即进入说话状态，不等待云端情绪。
- 收到 `tts stop` 或中止事件后立即退出。
- 云端情绪可以决定说话动画的情感风格，但不能取消“正在说话”的状态标识。
- 字幕滚动与眼睛动画相互独立，字幕更新不能反复重启动画。
- 第一阶段可使用固定说话动画；音频能量驱动的节奏变化作为增强项，只有在不影响音频任务实时性的情况下启用。

## 13. 儿童体验约束

- 唤醒确认优先使用短提示音和视觉反馈，不追加长句自我介绍。
- 非必要主动语音提示默认关闭。
- 微动作不能伴随随机说话。
- 错误信息使用简短、可理解的表达，例如“网络断开了”。
- 动画避免频繁快速闪烁；快速动画连续时间建议不超过 2 秒。
- 夜间亮度、音量和动画强度沿用设备设置，不擅自提高。
- 进入聆听后不播放会干扰儿童说话的持续音效。

## 14. 配置项

第一阶段提供编译期默认值，并预留后续运行时设置入口：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 角色表现系统 | 开启 | 可用于问题排查和回退 |
| 待机微动作 | 开启 | 关闭后使用稳定 idle |
| 微动作强度 | 低 | 低/标准两档，第一阶段可只实现低档 |
| 云端情绪增强 | 开启 | 关闭后只使用本地状态 |
| 情绪保持时间 | 5 秒 | P5 情绪的默认有效期 |
| 困倦等待时间 | 5 分钟 | 不得停止 WakeNet |
| 调试日志 | 关闭 | 输出决策来源、抢占和恢复原因 |

第一阶段不要求在屏幕设置页暴露这些选项，但代码结构不能阻止后续加入设置页。

## 15. 日志与可诊断性

每次实际表现切换应输出一条结构化日志，至少包含：

- 前一个行为；
- 新行为；
- 触发源；
- 优先级；
- 是否抢占；
- 预计持续时间；
- 被忽略请求及原因。

示例：

```text
Expression: idle -> listening source=device_state priority=P1 preempt=true
Expression: cloud_happy ignored reason=active_higher_priority active=listening
Expression: tool_success -> listening source=timeout restore=current_state
```

日志不得输出用户语音内容、账号信息、URL Cookie 或其他敏感数据。

## 16. 异常与降级

- 动画资源缺失或加载失败：记录错误，降级到 idle，不重启设备。
- 未知云端情绪：忽略，不清空当前表情。
- 连续快速状态切换：合并重复请求，避免频繁加载资源。
- 定时器创建失败：关闭待机微动作，不影响语音主链路。
- 内存不足：优先保留唤醒、聆听、说话和错误状态，关闭低优先级动画。
- 显示任务异常不得阻塞音频采集、播放、WakeNet 和网络任务。
- 音乐结束、TTS 中止、连接关闭等所有出口都必须触发表现状态重算。

## 17. 验收标准

### 17.1 功能验收

- [ ] 唤醒后 200 ms 内出现可辨识的唤醒或聆听反馈。
- [ ] 聆听、思考、说话三种状态仅看屏幕即可区分。
- [ ] `crying`、`sleepy`、`surprised` 不再显示 happy。
- [ ] 断网时能够区分连接中与连接失败。
- [ ] MCP 搜歌期间有持续的处理中反馈，成功和失败均能正常恢复。
- [ ] 云端不发送 emotion 时，完整对话流程仍有正确表情。
- [ ] 聆听期间收到 happy 等云端情绪不会覆盖聆听状态。
- [ ] TTS 被中止后不残留说话状态。
- [ ] 音乐自然结束和手动停止后都能恢复正确状态。
- [ ] 待机微动作间隔非固定，同一动作不连续出现。
- [ ] 任意微动作都不会阻止唤醒或触摸响应。

### 17.2 稳定性验收

- [ ] 连续进行 50 轮“唤醒—提问—回答—待机”无表情卡死。
- [ ] 连续播放并停止 20 首歌曲后，WakeNet 和表情状态均正常。
- [ ] 反复断网、重连 20 次无显示任务崩溃。
- [ ] 运行 8 小时后无明显持续内存下降。
- [ ] 表现系统关闭后，可回退到当前基础显示逻辑。

### 17.3 主观体验验收

邀请成人和儿童分别完成唤醒、提问、找歌三个任务，在不提示状态含义的情况下：

- 至少 80% 的测试者能区分聆听、思考和说话。
- 儿童不会因为额外语音或动画等待而错过说话时机。
- 用户认为待机更有生命感，但不会觉得频繁或打扰。

## 18. 实施拆分建议

### 里程碑 1：统一决策入口

- 建立 `ExpressionDirector`。
- 将设备状态和云端情绪接入统一入口。
- 定义优先级、超时、抢占和恢复机制。
- 保留开关，可快速回退现有逻辑。

### 里程碑 2：关键状态体验

- 修正现有情绪映射。
- 补齐唤醒、聆听、思考、工具执行、说话、连接和错误状态。
- 接入 TTS、MCP、网络与音乐生命周期事件。
- 增加状态切换日志。

### 里程碑 3：待机微动作

- 实现受约束的随机调度。
- 接入最近交互时间和困倦状态。
- 验证 WakeNet、触摸和高优先级事件能够立即抢占。

### 里程碑 4：设备实测与调优

- 执行功能与稳定性验收。
- 根据儿童实测调整动画时长和频率。
- 记录第二阶段需要新增的动画资产，不在本阶段临时扩张范围。

## 19. 第二阶段候选方向

以下只作为接口预留，不属于第一阶段承诺：

- TTS 音频能量驱动说话节奏；
- 更完整的眨眼、观察、困惑、哭泣、困倦动画资产；
- 音乐封面背景、旋转唱片、歌名和滚动歌词；
- 基于双麦声源方向的眼神朝向；
- 屏幕设置页中的角色表现强度和安静模式；
- 长期情绪连续性和用户偏好；
- 表情、灯效、触摸和提示音的统一行为编排。

## 20. 待确认事项
