# Phase Four：猫咪全场景覆盖与动作可达性

状态：2026-09-17 完整覆盖实现及本轮自动化验收已完成。长时间稳定性按用户要求跳过；真实 ASR 意图路由和物理屏幕观感仍明确保留为未验证。下文目标表为验收基线，实际证据与限制见实施记录。

## 目标与边界

- EchoEar 从第一帧开机界面至关机提示均使用新版猫咪视觉，不出现旧大眼睛资源；音乐封面模式保留。
- 以 `prototypes/character-phase-four.html` 中已确认的 8 类基础状态和 11 个动作作为清单，不重新设计眼睛、猫爪或乐器几何。
- 每项必须有正常使用入口、有限动作的自然结束规则、被打断后的恢复规则。仅在自检中可达不算交付。
- 不修改唤醒模型、收音策略、TTS 或音乐播放协议。动画不得延长收音启动，也不能要求说完回复才进入聆听。
- 长时间播放稳定性按用户要求跳过，始终记为未验证；不免除状态切换与音频并行的短时回归。

## 8 类基础状态覆盖

| 已确认状态 | 正常入口 | 生命周期 |
| --- | --- | --- |
| 安静待机 | 互动、动作和音乐结束 | 呼吸及眨眼持续；不跳回旧 neutral |
| 注意到你 | 唤醒确认 | 沿用现有短确认窗口，立刻允许聆听接管 |
| 专注聆听 | 唤醒、触摸、连续对话收音 | 稳定目光与轻微朝向变化；收音退出即结束 |
| 认真思考 | 等待回答、工具执行 | 持续等待动画，不能播放几秒后自动回待机 |
| 正在回答 | 实际 speaking 状态 | 说话时轻微动作，停顿/结束及时收敛；不把合成节拍称为真实音频同步 |
| 有点开心 | 正向云端情绪、操作成功 | 短反馈后回到当前实际状态 |
| 有点困惑 | 没听懂、可恢复失败、对应云端情绪 | 可打断；错误文案保留，不阻塞语音 |
| 慢慢困倦 | 无互动困倦、sleepy 情绪 | 揉眼结束保持猫咪困倦，互动立即恢复 |

新增有限动作请求入口与现有音乐乐器选择入口分开：表演不自动点歌，也不改变持久化的陪听偏好。请求先短确认，再在对话退出后执行；请求有过期时间且只保留一个待执行动作，不排长队。新的主动唤醒、触摸、音乐、错误或低电提醒取消待执行及进行中的表演。自动返回聆听不能错误地当作新的用户打断。工具说明必须区分“已接受待执行”与“已经播放完成”。

随机剧场保留统一 30–60 秒等待及 60 秒冷却、不连续重复；加入比心和躲猫猫，保留困倦降频及优先级约束。乐器不在安静待机时自动轮番出现，只通过明确表演请求或音乐陪听触发。

字幕和必要图标与猫咪层明确分层。保留原收音逻辑，聆听反馈使用猫咪状态，不让顶部旧波形抢占音乐或覆盖眼睛。不得通过隐藏所有文字来规避遮挡。

## 实施顺序与验收门槛

1. 移植基础状态的持续渲染及语义映射，测试参数边界、长时间戳、状态切换与动作保持。
2. 统一引擎启动、旧直调、失败回退和图层交接，确保第一帧与退出帧不泄漏旧眼睛；覆盖音乐中的真实聆听/说话接管。
3. 接入全部动作的有限请求入口和随机候选，验证取消、过期、自动聆听、音乐抢占及偏好不被修改。
4. 自动化遍历基础状态、所有云端情绪、11 动作和异常路径；自检用于可观测性，不能替代正常入口验证。
5. 编译后实机检查冷启动、联网、唤醒→聆听→思考→说话、情绪、困倦、错误、音乐进退、表演及打断。记录语音工具、实际选中状态和用户视觉反馈，逐项标记通过/未验证。

制定方案时的缺口：基础对话和辅助状态仍使用旧 EAF；比心/躲猫猫没有完整日常入口；11 个动作没有统一的正常语音表演入口。

## 实施记录

- 新增持续基础状态和悲伤、生气、惊讶变体，沿用已批准的直立胶囊眼、开心眼及爪子/乐器几何。说话起伏为状态驱动的轻动作，不宣称真实 TTS 能量同步。
- 导演统一映射开机、联网、聆听、思考、工具、说话、成功、错误及云端情绪；未知情绪退回新版中性。角色渲染失败退到固件内只读静态猫咪，不分配第二份兜底帧缓冲。
- 底层原眼睛对象改为图像对象，删除旧眼睛与旧顶部波形的 EAF 加载入口。动态角色复用该对象，字幕与图标保持在它上方。关闭动态渲染开关也只显示静态猫咪，不恢复旧眼睛。
- 新增 `self.screen.perform_cat_action(action)`，支持全部 11 个动作。只排一个有限请求，不修改陪听偏好；等待对话退出、过期或被新交互取消。返回排入检查不代表动作已经完成。揉眼自然结束保持困倦，新交互恢复。
- 空闲候选加入比心和躲猫猫，托腮权重仍为其他单项的两倍，等待/冷却规则不变。
- EchoEar 默认启用角色渲染与动态角色；音乐陪听、随机剧场和串口调试仍有独立编译开关。调试入口不作为生产用户入口。

## 可复现自动化

主机检查（需要 clang++；ffmpeg 可选，用于汇总关键帧）：

```sh
bash docs/prototypes/test-character-coverage.sh
```

检查旧 EAF 入口、真实导演映射、渲染边界/透明度/长时间戳、全部有限动作请求、取消/过期/替换、音乐阻塞、随机调度与持久化回归。生成 22 个姿态的真实 C++ 渲染关键帧，不能当作物理屏幕截图。

设备短时回归（需要 pyserial；`--reset` 另需 esptool，串口调试编译开关开启）：

```sh
python scripts/character_coverage_test.py \
  --port /dev/cu.usbmodem1201 \
  --output /tmp/echoear-cat-device-report.jsonl \
  --reset --music
```

输出路径必须不存在，避免覆盖历史证据。`--reset` 重启设备但不清除 NVS；`--music` 会实际播放官方测试音频并执行切歌/停止，不修改音乐显示偏好。运行时不要由其他程序占用串口。异常时脚本取消动作、恢复动态显示并请求停止测试音频。

自动注入使用真实导演、动作请求入口和渲染任务，记录已提交的实际姿态，而非只检查命令回执。状态注入不会改变真实麦克风或 TTS 状态，因此不能认定真实 ASR/云端意图路由、音频输入链路和物理屏幕观感均已验收。静态回退测试模拟渲染不可用标志，不是破坏性耗尽内存测试。长时间播放稳定性按用户要求跳过。

首轮短时设备测试已通过 53 项状态、动作及回退检查，但音乐启动未通过：`dl.espressif.com` 测试地址返回 302；核对其官方直达地址 `dl.espressif.cn` 返回 200，调试音频改用直达地址，没有修改生产播放器跳转策略。中性情绪重复通知不一定产生新的切帧，测试不要求它伪造重复渲染日志。最终固件另行重跑完整套件，首轮失败不得计为最终通过。
