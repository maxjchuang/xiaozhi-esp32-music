# Phase Four：空闲小剧场实施计划

状态：日常胶囊眼和唤醒挥爪已验证并提交（`4ab69d7`）；纯逻辑调度器及全部动作库已实现，动作库完成首轮实机验证；空闲随机调度和音乐陪伴尚未接入。

## 已确认的产品边界

以 `prototypes/character-phase-four.html` 为视觉与动作基准，不重新设计眼睛、猫爪或道具。不增加主动说话、音效、云端调用，也不启动音乐陪伴模式。小剧场只在安静待机时发生；真实互动、音乐、错误和低电量提示优先，动作被打断后不续播。

原型自动动作池为：安静档托腮（较高权重）、吹泡泡、捉小鱼；活泼档增加躲猫猫。比心不在原型自动动作池中，本轮不擅自加入。揉眼睛用于困倦过渡，乐器属于后续音乐陪伴。

## 实施顺序

1. **纯逻辑调度器及测试。** 注入单调时钟和随机数，脱离 ESP-IDF 做确定性测试；暂不启用自动表演。
2. **移植动作。** 先吹泡泡、捉小鱼，再托腮、躲猫猫及困倦揉眼。沿用原型时间轴、入场/退场和视线联动，不用静态道具代替完整动作。通过调试入口逐个验证造型、帧率、恢复和中断，再启用随机调度。
3. **接入导演。** 增加低优先级空闲行为，由现有导演选定最终显示；渲染任务只执行选定动作，不自行覆盖聆听/音乐图层。动作自然结束返回胶囊眼。
4. **实机自动化与人工验收。** 自动验证调度边界、动作完成/中断/恢复、内存和帧率；人工确认实际视觉及麦克风/触摸链路。通过后再提交小剧场实现。

## 调度规则

- 模式：关闭、安静、活泼；试用开关默认关闭，开启试用时默认安静。首轮使用编译配置，不额外建设后台配置界面或修改 MCP。
- 首次等待：安静 90–180 秒，活泼 45–90 秒。动作结束后至少休息 120 秒；同一动作不连续出现。
- 5 分钟无用户互动后，候选等待间隔加倍；10 分钟无互动进入困倦，停止自动表演。自动表演本身不算用户互动。
- 当前固件 `ECHOEAR_IDLE_SLEEP_TIMEOUT_SECONDS=300`，与上述原型不同：只在小剧场试用模式统一采用 600 秒的视觉困倦边界；关闭试用仍保留原配置。不得改动硬件休眠、低电量关机策略。
- 忙碌时取消当前动作及待触发事件；回到稳定待机后重新等待，不补播积压事件。中断也计入冷却；不因状态重复通知清空历史动作或冷却时间。
- 音乐播放/暂停/缓冲、连接、聆听、说话、工具执行、错误/充电提醒、自检时不触发。无在场检测，不能据此认定儿童仍在设备旁。

## 渲染与资源约束

复用已验证的日常渲染任务和双缓冲，按需缓存静态部分，不为每个动作永久保留全帧缓存。姿态变更、退出和缓冲释放沿用同一互斥机制。失败时恢复原资源表情，避免反复申请失败。

把 `character_pose` 的试用整数标记收敛为命名动作枚举，显式区分循环待机和有限时长表演；明确结束时间和清理责任。几何、定时、调度分别测试，防止动作池扩展后数字映射混乱。

## 自动验收要求

- 固定随机种子验证两档等待范围、120 秒冷却、不连续重复、忙碌互斥、5/10 分钟边界及关闭/重开行为。
- 测试时推进虚拟时钟，不在发布固件缩短真实等待时间；实机加速仅通过默认关闭的调试入口开启，不改变动作速度。
- 每个动作至少 10 轮完整播放，分别在开始、中段、结束前软件中断，再恢复完整播放。不能把软件取消当作真实唤醒测试。
- 至少 20 fps 平均提交帧率作为初步性能目标，记录最慢帧、栈余量、缓存申请及释放后内存；不将提交帧率等同于屏幕刷新率。
- 首先取得真实待机 90–180 秒后自动触发的一次记录，再进行加速压力测试。高优先级接管无道具残留、无新旧眼形交叉，不为完成动作延迟语音收音。
- 场景回归：唤醒、触摸、连续对话、播歌、换歌、停止及自然结束；长时待机功耗另行测量。

## 本轮不包含

音乐节拍联动、乐器陪听、更多角色性格、后台远程配置、使用行为上报、唤醒模型调整及固件发布默认开启。

## 实施记录：纯逻辑调度器

新增 `main/boards/echoear/idle_theatre.h` 与 `docs/prototypes/test-idle-theatre.cc`。调度器不依赖 ESP-IDF，调用方提供单调毫秒时刻、随机数、模式、是否可表演，以及是否发生真实用户互动。输出当前命名动作、开始/停止边沿、困倦状态和下一次检查时刻；下一次检查可能是策略边界，不一定是动作开始时间。

已实现等待范围、托腮权重、不连续重复、自然结束、中断冷却、重复通知幂等、关闭/重新开启、忙碌后重新等待及 5/10 分钟边界。越过 5 分钟时，尚未开始的等待重新按降频区间安排；10 分钟困倦优先于当前小剧场，揉眼仅尝试一次，被打断后不续播，直到真实互动重置。迟到调用不补播旧动作；时钟回退被钳制，不能回退冷却时间。时间加法使用饱和处理。

```sh
clang++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -I main/boards/echoear docs/prototypes/test-idle-theatre.cc \
  -o /tmp/echoear-idle-theatre-test
/tmp/echoear-idle-theatre-test
```

边界测试及固定种子 24 小时模拟通过（502 次表演），包括等待区间端点、冷却、权重与动作池、困倦抢占、取消后恢复及忙碌互斥。测试在主机虚拟时间运行，不代表设备持续运行了 24 小时。

当前调度器尚未被导演调用，没有更改设备的 300 秒困倦配置，没有自动随机表演，也没有新增固件开关或烧录。下一步是移植吹泡泡与捉小鱼的绘制及入退场，先经调试入口验收，再接入自动调度。
